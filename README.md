Краткий вывод такой:  
Так как расчет для latency и energy был для worst case сценария, то всегда теоретические значения превышают практические.
Это говорит нам о том, что железо работает эффективнее, чем в теории, и в коде куча оптимизаций, которые сильно уменьшают время одного прогона

Калибровочные коэффициенты получились:
```
{
    "THETA_LAT" : [-42.0574, 1.3477],
    "THETA_EN"  : [-4.3897,  146.2250]
}
```
И все равно реальные значения всегда меньше, чем теоретические
